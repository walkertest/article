# 问题
- 仓库的体积多达1.2GB，下载下来后目录的体积大概1.5GB，在网络不好的时候，下载时间非常久，还可能会失败.
- 本文通过工具去分析大的文件，以及移除这些大文件，让仓库更加整洁.

# 原因
git 的核心设计决定了这一点：每一次 git clone 都会拉取从第一次提交到最新提交的完整历史。Git 的对象存储机制（.git/objects）是追加式的——文件一旦被提交，就会作为一个 Blob 对象永久存在于仓库中，即使后续提交中将其 git rm 删除，该文件的数据依然保留在历史快照里。
举个例子：如果有人在第 100 次提交时误传了一个 500MB 的压缩包，然后在第 101 次提交时删除了它。那么：
仓库的 .git 文件夹会永久多出至少 500MB（压缩后可能略小，但二进制文件压缩率很低）。
每一个执行 git clone 的人，无论他是否需要那个文件，都必须下载这 500MB 的数据。

# 解决方案的详细步骤
- 通知组内同学将手头更新推进远程分支（需要推送，不推送的话，后续会推送不上去），停止代码仓库的更新，能合并到master的代码，尽量合并到master
- fork代码仓库，作为备份仓库(zbase-backup)，并切断关联关系. （同时多位开发同学，本地也有备份）
- 在原来的仓库中，使用git-filter-repo去清理大文件历史记录,并本地Check仓库大小，确认改动是否生效
- 将原来的仓库改名为zbase-rname，在gitlab服务器上新建一个同名zbase仓库，将本地修改后的内容，推到新仓库
- 整个过程持续20分钟左右
- 大家重新克隆代码，验证各自服务的构建、运行和代码提交历史等是否有问题

- 如果有问题，将备份的仓库重新fork回来即可

- 方案特点：commit和分支以及tag都在，wiki、issue、merged request会丢失，commitid会被重写，在备份仓库中可以找到.

## 思路一
- git-sizer + bfg
- 这个方案试验后不好用，主要是bfg不支持正则和准确位置删除


## 思路二：使用git-filter-repo分析和清理大文件
- 完整攻略，在gitlab的Repository cleanup处也有指引，也是建议这种方案，本文的方案和官方方案的区别点在于不用gitlab服务器的清理能力（试了不生效）
- 安装：pip install git-filter-repo，需要将对应的脚本命令加到path路径下面，才能够正常使用命令
- 分析：git-filter-repo --analyze,去对应的文件下面查看分析结论即可
- 删除具体的文件：git-filter-repo --path zbase-cloud/heap.bin --path apollo/apollo-configservice/target/apollo-configservice-0.10.2-github.zip --path apollo/apollo-adminservice/target/apollo-adminservice-0.10.2-github.zip --path apollo/apollo-portal/target/apollo-portal-0.10.2-github.zip --path apollo/apollo-portal/target/apollo-portal-0.10.2.jar --path apollo/apollo-configservice/target/apollo-configservice-0.10.2.jar  --invert-paths
- 删除正则表达式的文件：git-filter-repo --path-regex '^zbase-cloud/app_html/src/main/resources/public/static/ele/static/js/chunk-[a-f0-9]+\.[a-f0-9]+\.(js|js\.map)$' --invert-paths --force
- 物理删除：git reflog expire --expire=now --all && git gc --prune=now --aggressive
- 重新建立远程仓库关系（新建一个同名的仓库）：git remote remove origin && git remote add origin https://gitlab.example.com/<namespace>/<project_name>.git
- push本地仓库到新的远程仓库：
- git push origin --force 'refs/*'
- git push origin --force 'refs/heads/*'
- git push origin --force 'refs/tags/*'
- git push origin --force 'refs/replace/*'
- 这样就把代码、提交记录、tag、分支等push到了新仓库.


# 优化效果
- 体积：1.2G 到 300M
- clone时间：优化前：1.16s，优化后43s(和网络状况相关)

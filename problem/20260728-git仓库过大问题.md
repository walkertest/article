# 问题
- 仓库的体积多达1.2GB，下载下来后目录的体积大概1.5GB，在网络不好的时候，下载时间非常久，还可能会失败.
- 本文通过工具去分析大的文件，以及移除这些大文件，让仓库更加整洁.

# 原因
git 的核心设计决定了这一点：每一次 git clone 都会拉取从第一次提交到最新提交的完整历史。Git 的对象存储机制（.git/objects）是追加式的——文件一旦被提交，就会作为一个 Blob 对象永久存在于仓库中，即使后续提交中将其 git rm 删除，该文件的数据依然保留在历史快照里。
举个例子：如果有人在第 100 次提交时误传了一个 500MB 的压缩包，然后在第 101 次提交时删除了它。那么：
仓库的 .git 文件夹会永久多出至少 500MB（压缩后可能略小，但二进制文件压缩率很低）。
每一个执行 git clone 的人，无论他是否需要那个文件，都必须下载这 500MB 的数据。

# 解决方案的详细步骤
- 通知组内同学，停止代码仓库的更新或者将手头更新推进远程分支，能合并到master的代码，尽量合并到master
- fork代码仓库，作为备份仓库(zbase-backup)，并切断关联关系. （同时多位开发同学，本地也有备份）
- 在原来的仓库中，使用git-filter-repo去清理大文件历史记录,并本地Check仓库大小，确认改动是否生效
- 将原来的仓库改名为zbase-rname，在gitlab服务器上新建一个同名zbase仓库，将本地修改后的内容，推到新仓库
- 整个过程持续20分钟左右
- 大家验证各自服务的构建和代码提交历史是否有问题

- 如果有问题，将备份的仓库重新fork回来即可

- 方案特点：commit和分支以及tag都在，wiki、issue、merged request会丢失，在备份仓库中可以找到.

## 使用BFG Repo-Cleaner 清理大文件
- 下载bfg jar包：https://rtyley.github.io/bfg-repo-cleaner/?spm=5176.28103460.0.0.96a02988yBe5hh
- java -jar /path/to/bfg.jar --delete-files 'some-large-file.zip' your-big-repo.git
- 执行删除动作：java -jar /g/software/java/bfg-1.15.0.jar --delete-files 'heap.bin' zbase-backup/
- 物理删除：git reflog expire --expire=now --all && git gc --prune=now --aggressive
- git push --force-with-lease origin <branch-name>
- git push origin --force --all
- git push origin --force --tags


## 使用git-filter-repo去清理大文件
- 完整攻略，在gitlab的Repository cleanup处也有指引
- 安装：pip install git-filter-repo，需要将对应的脚本命令加到path路径下面，才能够正常使用命令
- 分析：git-filter-repo --analyze,去对应的文件下面查看分析结论即可
- git-filter-repo --path zbase-cloud/heap.bin --path apollo/apollo-configservice/target/apollo-configservice-0.10.2-github.zip --path apollo/apollo-adminservice/target/apollo-adminservice-0.10.2-github.zip --path apollo/apollo-portal/target/apollo-portal-0.10.2-github.zip --path apollo/apollo-portal/target/apollo-portal-0.10.2.jar --path apollo/apollo-configservice/target/apollo-configservice-0.10.2.jar  --invert-paths
- git-filter-repo --path-regex '^zbase-cloud/app_html/src/main/resources/public/static/ele/static/js/chunk-[a-f0-9]+\.[a-f0-9]+\.(js|js\.map)$' --invert-paths --force
- 上面这一步会生成一个对象文件：.git/filter-repo/commit-map
- git reflog expire --expire=now --all && git gc --prune=now --aggressive

- git remote remove origin
- git remote add origin https://gitlab.example.com/<namespace>/<project_name>.git
- git push origin --force 'refs/*'
- git push origin --force 'refs/heads/*'
- git push origin --force 'refs/tags/*'
- git push origin --force 'refs/replace/*'
- 记录上面执行完成的时间：15:37，等至少三十分钟，比如16:30
- 第二次16:47执行完成，等17:30
- 在gitlab的仓库管理页面中执行 repository cleanup,这里会用到上面生成的对象文件


# 优化效果
- 体积：1.2G 到 300M
- clone时间：1分39s，优化前：1分12s，原来仓库：1.16s，优化后43s.
